# 点子验证方法论 playbook

> 创业失败的首要原因是"做没人要的产品"。本 playbook 给一套在写代码之前就能低成本验证点子的流程。

## 1. 三问前置（先回答再动手）

```
Q1 问题是否真实紧迫？  — 用户现在用什么凑合？痛到愿意付钱/换方案吗？
Q2 市场时机对吗？     — 技术/监管/习惯是否已就绪？早一步是先烈，晚一步是跟风。
Q3 商业数学成立吗？   — 客单价 × 可触达人数 × 转化率 能否覆盖获客与交付成本？
```

三问任一答不上来，先别写代码。

## 2. 验证阶梯（由廉价到昂贵）

```
1. 访谈 10 个目标用户      — 听真实痛点，不推销想法
2. 假门测试（Landing Page） — 放"加入等候名单/预付"，看是否有人动作
3. 手动服务（Wizard of Oz）— 后端全人工，前端像产品，验证流程可行
4. 真实 MVP                — 仅当有前序证据，再投入开发
```

**原则**：能用访谈和假门验证的，绝不先写代码。

## 3. 失败信号（及时止损）

- 访谈中用户说"挺有意思"但从无行动
- 假门页面有流量无转化
- 愿意预付的人为 0
- 你自己都说服不了第一个用户

## 4. 验证前检查清单

- [ ] 目标用户已明确（不是"所有人"）
- [ ] 至少一个廉价验证手段已设计
- [ ] 成功/失败标准前置定义
- [ ] 设定时间盒（避免无限"再调研"）

## 5. 常见坑

- **自嗨验证**：只搜集支持自己想法的信息，忽略反对证据。
- **跳过验证直接开发**：几个月做出没人要的东西。
- **把观点当需求**：用户说"我会用"≠ 真会用，看行动不看表态。
- **没有时间盒**：永远在"调研"，从不交付。

## 6. 相关子技能与层次边界

本 playbook 只给**验证阶梯的决策与止损信号**（L2 方法论）；具体产出怎么写、模板怎么套，交给下列子技能（L3 落地）：

| 落地需求 | 调用子技能 |
|----------|-----------|
| 逐项评估点子（市场时机 / 商业数学 / 需求框架） | `skills/idea-validator/SKILL.md` |
| 验证通过后构建最小可交付单位（手动 → 流程化 → 产品化） | `skills/mvp-builder/SKILL.md` |
| 用访谈与早期成交换取真实付费证据 | `skills/founder-sales/SKILL.md` |

**层次边界**：本文回答「该不该继续、什么时候停」；子技能回答「这一步具体怎么做、交付什么」。第 2 节验证阶梯的第 4 阶（真实 MVP）不在本文展开，直接进 `skills/mvp-builder/`；第 3 节失败信号若来自销售侧，配合 `skills/founder-sales/` 复盘话术而非直接砍方向。

**兄弟 playbook**：验证通过并累积 traction 后再谈钱 → `references/fundraising-readiness.md`。
